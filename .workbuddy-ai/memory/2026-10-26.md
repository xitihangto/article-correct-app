- lecture-app 当前基线 v0.27，纯 swiftc 手工组 bundle，无 Xcode 工程，产物约 77MB（75MB 为内置 CPython 3.12 + python-docx）。
- 核心架构：SwiftUI 主窗口 + 隐形 WKWebView（alpha=0 + ignoresMouseEvents）驱动 chat.deepseek.com → 上传「规则.md + 模板.docx + 用户两份 docx」→ 提示词要求 AI 输出 Python 脚本并以 `# ===LECTURE-END===` 收尾 → 四层判定写完 → 抓 `.md-code-block pre` → 内置 Python 执行 → docx → 常驻 Word 卡下载。
- 必须原样继承的铁律（HANDOVER 明确记载）：
  1. 「继续生成」只能用真实 NSEvent 注入（页面校验 isTrusted），JS 点击无效。
  2. 量长度用 `textContent`，绝不用 `innerText`。
  3. 隐藏浏览器用 alpha=0，不用挪到屏幕外（会被判 hidden 节流、双屏漏出）。
  4. 结束判定：结束标记连续 2 轮 / 收尾标志+afterLines>=3 / 稳定 60 秒且必须有收尾标志；总上限 10 分钟，绝不执行截断脚本。
  5. 任何视觉叠层不得挡住点击（`allowsHitTesting(false)`），功能优先于外观。
  6. 版本纪律：改动前先升 build.sh 版本号，改动→本地编译安装试用→用户说上线才 push tag→CI 出 Release。

## 环境坑（下次直接用）

- 本机 `swiftc` 直接编译会报 `SwiftUIMacros ... malformed response`，根因是 swift 驱动用 `sandbox-exec` 起宏插件服务被拒。**加 `-disable-sandbox` 即可**，`build.sh` 已自动探测加参。
- 本环境 Bash 的 `grep` 查中文常返回空/exit 1，查代码一律用 Grep 工具。
- 截图验证 UI 前必须先 `killall EssayCorrect`，否则 `open` 会复用旧实例，看到的是旧状态。
