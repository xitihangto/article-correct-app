# 规则 md 清理对照表

> 用途：用户会重新提供一版《作文批改规则.md》（以及配套模板 docx），两份都是他自己优化过的。
> 这份表是**换版时的检查清单**：哪些段落是写给 agent 的、必须删或改写；哪些是脚本必须遵守的、一个字都不能丢。
>
> 核心判断标准只有一句：**这份 md 的读者不是 agent，是「一段由 AI 写出来、由 App 执行的 Python 脚本」。**
> 凡是「让 agent 去做什么」的话都没有约束力，因为执行者已经换成脚本了。

---

## 一、必删：写给 agent 的「交付动作」

| 典型原文 | 为什么删 |
|---|---|
| 直接输出 .docx 文件交给用户下载 | 网页版 AI 给不出文件，交付物是**脚本**；文件是脚本跑出来的 |
| 不要在对话里贴正文 | 同上，这是对聊天界面的约束 |
| 保存在会话工作区根目录 / 存到 `jiangyi/` | 路径由 App 的临时沙箱决定，AI 指定也没用 |
| 文件名默认 `<学校><学年>…docx` | 保留**命名规则**可以，但要说清「脚本里 `doc.save()` 用这个名字」，而不是「你保存成这个名字」 |

**改写方向**：把「你去保存」改成「脚本用 `doc.save('X.docx')` 保存」。

---

## 二、必删：写给 agent 的「自检与流程」

| 典型原文 | 为什么删 |
|---|---|
| 不做格式自检，只关注内容 | 自检主体是脚本，AI 自检不产生任何效果 |
| 生成后仅做一次轻量结构校验（能否打开、段落数…） | 要么删，要么改成「脚本保存前 assert 这几项」 |
| 我会肉眼检测排版，你只要关注内容 | 用户口头习惯，对脚本零约束 |
| 标准流程：读三份 docx → 通读模板 → 用 Book 逐块写入 → save | 这是 agent 的操作步骤；脚本只有「读 → 写 → 存」三步，且顺序由代码决定 |
| 中间产物（build 脚本、文本 dump、patch 脚本）留在子目录 | 纯 agent 工作习惯，脚本没有中间产物 |

**改写方向**：需要保留的校验，一律写成「脚本里必须做 X」，并给出可执行判据（数量、正则、计数）。

---

## 三、必删：重复声明运行环境

| 典型原文 | 处理 |
|---|---|
| 工作区自带 Python / 已装 python-docx / 不要 import 第三方库 | 提示词里已经统一声明，md 里重复只会互相打架 |
| 具体 python 解释器绝对路径 | 绝对路径是别人机器的，写进 md 会让 AI 抄进脚本 |
| 不要用 input() 等待键盘输入 | 属于提示词范畴；md 里可以留一句「脚本必须一次跑完、无交互」作为原则 |

---

## 四、必删：元信息与生效范围

| 典型原文 | 为什么删 |
|---|---|
| 不登记到 `~/.dsh/AGENTS.md`、不改动全局配置 | 对脚本毫无意义 |
| 本规则仅在本次对话内有效 | 相反：md 是随包分发的内置附件，每次都要生效 |
| 用户不需要时可随时删除 | 运维说明，不属于规则 |
| 变更日志（用户历次意见表） | 对生成脚本没有信息量；移到 `HANDOVER.md` 存档更合适 |

---

## 五、必改：把「你」改成客观规则

凡出现第二人称「你」的地方，都要改成对产物的描述：

| 现在 | 改成 |
|---|---|
| 请你自行根据内容判断哪个是文章 | 输入文件按内容判定：含 Directions / 中文要点提示的是题目；含学生本人语言错误的是作文 |
| 由你根据作文题目要求提出修改意见 | 修改意见须针对题目要点逐条落实，缺一条即为不合格 |
| 请你给出 Python 脚本 | （这句属于提示词，不属于规则 md） |

---

## 六、一个字都不能丢：脚本必须遵守的硬规则

这些是业务本身，换版时逐条核对有没有被误删：

1. **四段结构固定且有序**：一、作文要求 → 二、学生作文 → 三、修改意见（纠错＋补充）→ 四、终稿。
2. **版式数值**：A4 21×29.7cm；上下 2.0cm、左右 2.2cm；行距 1.15；段前段后 0；正文首行缩进 12pt；中文宋体、英文 Times New Roman（ascii/hAnsi/cs 都设）。
3. **字号层级**：标题 14 加粗居中、一级标题 12 加粗、二级 11 加粗、正文 10.5、括注 9、蓝编号 8.5。
4. **颜色分工**：黑 `000000` 原文、红 `FF0000` 需改处、蓝 `1F4E79` 溯源编号。红只标词或短语，不整句标红。
5. **纠错必须重录原文**，格式 `纠N·标题　<原文，需改处红字>　→　修改为：<英文>`。
6. **补充意见必须给可直接插入的英文原句**，格式 `意N·标题　位置：…　增加：…`。
7. **编号一一对应**：终稿每句后挂〔纠N〕/〔意N〕，第三段有几条就得出现几个编号。
8. **禁止项**：`keepNext`、`keepLines`、`numPr`、段间空行、表格、`add_heading` 等内置样式。
9. **内容尺度**：上海高考 25 分、目标 20+ 档；只改真错、不改学生立场与要点；终稿词数在题目区间且不超上限 10%。
10. **终稿是唯一版本**，不是并列多版；必须完整（称呼、正文、结束语、署名）。

---

## 七、换版后的验收动作

1. 替换 `Resources/作文批改规则.md`，改 `build.sh` 版本号。
2. `./build.sh` → `--selftest` 确认 `ruleHead` 读到了新文件。
3. 跑一轮真实生成，检查产物：
   - `w:keepNext` = 0、`w:numPr` = 0
   - 红字 run > 0，蓝编号 run > 0
   - 四段标题齐全
   - 纠错条数 == 终稿编号种数
4. 提交并打 tag。
