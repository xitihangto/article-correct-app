# 高三英语「作文批改」生成规则（已固化）

> 适用：把【作文题目】+【学生作文】+《标准模式批改》三份材料合成为一份可直接发给学生的 Word 批改稿。
> 本文件是历次修改意见的汇总，后续新增意见一律追加到文末「变更日志」，并按最新规则执行。

---

## 0. 交付方式

- **直接输出 .docx 文件**交给用户下载，**不要在对话里贴正文**。
- **不做格式自检**，只关注内容本身；生成后仅做一次轻量结构校验（能否打开、四段是否齐全、颜色是否写入）。
- 文件名默认：`<题名>批改与升格.docx`，保存在会话工作区根目录。
- 文件属性判断：三份输入文件命名不一定对应，须**按内容判断**哪个是作文题目、哪个是学生作文、哪个是标准模式。
  - 题目：含 Directions / 中文写作要求 / 要点提示，通常很短。
  - 学生作文：书信或议论文正文，含学生本人的语言错误，可能注明「手写稿」。
  - 标准模式：已经批改好的完整成品，用于照版式，**不要抄它的内容**。

## 1. 全局排版（照搬《标准模式批改》）

| 项目 | 取值 |
|---|---|
| 页面 | A4（8.27 × 11.69 英寸） |
| 页边距 | 上下 2.0 cm，左右 2.2 cm |
| 中文字体 | 全文**宋体**（SimSun） |
| 英文字体 | 全文 **Times New Roman**（ascii / hAnsi / cs 均设，eastAsia 单设宋体） |
| 行距 | 1.15（`w:line=276`，`lineRule=auto`） |
| 段前 / 段后 | 全部 0；**段落之间不留空行** |
| 首行缩进 | 正文段落 12 pt（约 0.42 cm），标题、括注、图例不缩进 |

### 字号与颜色（run 类型表）

| kind | 用途 | 颜色 | 加粗 | 字号(pt) |
|---|---|---|---|---|
| `title` | 主标题「高三英语写作训练《题名》批改与升格」 | `000000` | ✔ | 14 |
| `sub` | 副标题 / 颜色图例 | `000000` | | 9 |
| `h1` | 一、作文要求 / 二、学生作文 / 三、修改意见 / 四、终稿 | `000000` | ✔ | 12 |
| `h2` | （一）纠错 / （二）补充意见 | `000000` | ✔ | 11 |
| `n` | 正文（原文、修改意见行、终稿） | `000000` | | 10.5 |
| `fix` | **需修改处** | `FF0000` | | 10.5 |
| `tag` | **终稿溯源编号**〔纠3〕〔意1〕 | `1F4E79` | | 8.5 |
| `note` | 括注（词数、图例、说明） | `000000` | | 9 |

> 颜色三位一体固定：**黑＝原文保留、红＝需要修改处、蓝＝终稿与意见的对应编号**。
> 凡「同类情形」一律沿用这套配色，不得自创第四种颜色。

### 版式硬规则

- **禁止使用 `keepNext` / `keepLines`**：Word/WPS 会在段落左侧显示黑色方块标记（用户明确要求不得出现）。
- **禁止段间空行**：段落之间靠段前段后 0 + 行距 1.15 排开，不插空段落。
- **禁止项目符号 / 编号列表**：全文 `w:numPr` 计数必须为 0；编号一律手写在文字里（`纠1·`、`意1·`）。
- **禁止表格**：整份批改稿不使用表格；若原文本身是表格，按原文保留。

## 2. 四段结构（固定顺序，缺一段即不合格）

```
一、作文要求
二、学生作文（手写原文完整转录）
三、修改意见（纠错 ＋ 补充意见）
四、终稿
```

### 2.1 一、作文要求

- 原题的英文 Directions **原文照录**（含大题号、分值，如 `IV. Guided Writing (25%)`）。
- 中文写作要求逐条照录（`1. 你的立场` `2. 你的理由` 这类），保留原编号。
- **不翻译、不改写、不总结、不评价**。题目要求有几个要点就列几条。

### 2.2 二、学生作文

- 手写稿必须**完整转录为可读正文**，段落照原文分段。
- **保留学生原有的一切语言错误与表达习惯**，一个错都不改，一个词都不润色。
- 首行缩进 12 pt；称呼语、结束语、署名照原文（原文缺署名就缺，在下面括注里说明）。
- 正文结束后加一行 9 pt 括注：
  `（正文共 N 词；手写原文完整转录，保留原有语言表达与错误；<缺什么就写什么>。）`

### 2.3 三、修改意见（纠错 ＋ 补充意见）

段首先给两行 9 pt 图例，一字不改：

```
【纠错】原文的语言硬伤，必须改。
【补充意见】原文没错、但补上能更充实更贴题的内容。
```

#### （一）纠错

每条**独占一段**，格式固定：

```
纠N·<标题>　<重录原文整句，其中需改的词用红字>　→　修改为：<改后的表达>
```

- **必须重录原文**，不许写成「某句有问题，建议改一下」。用户的原话是：修改意见不是凭空给意见，而是重新列一遍原文，红字显示需改处，紧跟修改意见。
- **红字只标要改的词或短语**，不整句标红、不整段标红。
- `<标题>` 4–10 个字，说清错在哪：语法硬伤 / 搭配错误 / 拼写 / 语义说反 / 冗余并列 / 主客颠倒 / 万能收尾 / 落款缺失。
- 按原文出现顺序编号 `纠1…纠N`，**不跳号、不重号、不合并**。
- 「修改为」要给**可直接替换的英文**，不是「建议改为更地道的说法」。
- 只在确有硬伤时列；原文正确的地方不硬凑条目。

#### （二）补充意见

每条**独占一段**，格式固定：

```
意N·<标题>　位置：<第 X 段，某句之后>。　增加：<可直接插入的英文句子>
```

- 补充意见的定义是「原文没错，但补上更好」：补例证、补层次、补回扣、补细节。
- **必须给出可直接插进终稿的英文原句**，不许只给「建议加强论证」这类空话。
- 编号 `意1…意M` 独立于纠错编号，两者不混用。

### 2.4 四、终稿

- **只给一个版本**，不并列「修改版 A / 修改版 B」。
- 段首先给 9 pt 括注：
  `（唯一版本，N 词；每句后小号蓝色〔〕为该句落实的意见编号。）`
- 正文里**每句之后紧跟蓝色小号溯源编号**：`〔纠2〕`、`〔意3〕`、`〔纠5、纠6〕`（多个用顿号）。
- 编号必须与第三段**一一对应**：第三段有几条，终稿里就该出现几个编号；没被任何意见涉及的句子不加编号。
- 终稿必须是**完整可交的文章**：称呼、正文、结束语、署名齐全；原文缺失的落款要在终稿补齐，并在纠错里说明是补的。
- 终稿词数控制在题目要求区间（通常 120–150 词），**不得超过上限 10%**。

## 3. 语言与内容标准（上海高考难度）

- **定位**：上海市高考英语写作（25 分），目标 20+ 分档。按这个档次判断「该不该改、改成什么」。
- **只改真错**：拼写、时态、主谓一致、搭配、并列结构不一致、从句套谓语、代词指代、语义说反、口语缩写入文。
- **不为改而改**：原文正确且得体的句子保持不动，终稿要能看出是**这个学生**写的，不是范文。
- **词汇升级要有理由**：优先精确度、搭配、语域；不堆砌大词，不用学生不可能写出的表达。
- **句式**：避免连续简单句；允许一处强调、倒装或非谓语结构提亮，但不炫技、不超过两处。
- **不替学生改立场与要点**：观点、理由、例子都按学生原有的走，只改表达。
- **书信体要守格式**：`Dear ...,` 开头，`Yours sincerely,` / `Best wishes,` 结尾，署名 `Li Hua`；正文用书信语域，不用论文语域。

## 4. 禁止项（违反即返工）

- 段间空行、`keepNext`、编号列表、表格 —— 见 §1 版式硬规则。
- 整句或整段标红。
- 修改意见只写「建议…」而不重录原文。
- 补充意见只给中文建议、不给英文原句。
- 把学生作文改写成范文、抽掉学生自己的思路。
- 终稿与第三段编号对不上（多号、少号、错号）。
- 在批改稿里加入评语、打分、教师签名、日期等题目没要求的内容。
- 用 `add_heading` 之类内置样式（会带出主题字体和间距，破坏版式）—— 一律用 `add_paragraph` + run 级设置。

## 5. 工具与流程

1. 用 `python-docx`（运行环境自带）生成，不要 import 其他第三方库。
2. 标准流程：
   - 读三份 docx，逐段导出「文本 + 字号 + 颜色 + 加粗」，据此判断文件属性；
   - 通读《标准模式批改》，只提取**形式**（四段结构、字号层级、红蓝用法、括注写法），不抄内容；
   - 逐段写入：标题 → 副标题 → 四段正文 → 括注，run 级设字体字号颜色；
   - `doc.save()` 保存，文件名见 §0。
3. 保存前的轻量校验（代码里做，不写进文档）：
   - 四段标题齐全；
   - 纠错条数 == 终稿里出现的纠错编号种数；
   - 红字 run 数 > 0；
   - 终稿词数在题目要求区间；
   - `w:keepNext` 计数为 0、`w:numPr` 计数为 0。

## 7. 生效范围

- 本规则用于本 App 的每一次批改任务，**仅在本次生成内有效**。
- 不登记到任何全局配置，不改动 `~/.dsh/AGENTS.md`。
- 本文件与《标准模式批改.docx》是 App 的内置附件，随包分发，用户不需要时可自行替换。
